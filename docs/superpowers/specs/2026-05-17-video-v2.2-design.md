# Video Agent v2.2 — Cinematographer

**Status:** Approved design, ready for implementation plan
**Date:** 2026-05-17
**Branch target:** `video-v2.2-cinematographer`

## Problem

Pipeline output is ~70% of where it needs to be. Four concrete failures observed in the latest rendered video:

1. **Scene visuals lack cumulative narrative context.** The Sourcer scores each candidate against *that scene's narration only*. When the voiceover arc is "calcium ions cause scaling in equipment → pH rises → equipment fails", the per-scene matcher picks a generic high-pH river photo because the caption keyword-matches the current line, ignoring the topical thread (equipment / industrial water / pipe scaling).
2. **Outro is templated and disconnected.** `composer._OUTRO_CTA_TEXT` is a hardcoded string and `OUTRO_VIDEO_PATH` is a pre-rendered card. The Strategist-written CTA gets truncated to fit; a generic CTA is bolted on. No flow from main video into outro.
3. **Hook has no vocal emphasis.** `voiceover.synthesize` renders the entire narration as one `edge_tts.Communicate` call with one `TTS_RATE` and one `TTS_PITCH`. The hook is delivered in the same monotone as the proof beat.
4. **Visual-effects mapping is a static lookup.** `color_grade.grade_filter_for_mood` and `transitions.transition_between` are hardcoded `mood → effect` maps. No model agency to decide *this* shot needs cold-blue, *that* transition needs a whip-pan.

Additionally, the Google Images source spawns a fresh tab per query and uses a naïve hand-rolled stealth shim — Google's CAPTCHA frequency is the symptom.

## Solution Overview

Six loosely-coupled patches landing in one branch:

- **Patch A** — New `Cinematographer` agent stage (gemma 4 tool-call shim).
- **Patch B** — Cumulative-context Sourcer with narrative-thread keywords.
- **Patch C** — Real CTA-as-final-scene outro + silent 2s logo stinger.
- **Patch D** — Per-scene SSML prosody in voiceover.
- **Patch E** — Gemma 4 thinking-mode + sampling config in `OllamaClient`.
- **Patch F** — Persistent stealth browser for Google Images.

New agent pipeline order:

```
Strategist → Storyboarder → Cinematographer (NEW) → NarrationPolisher → Sourcer → Critics → Reviser
```

## Patch A — Cinematographer agent

**New file:** `video_agent/agents/cinematographer.py`

Given the full storyboard (hero claim, all scene narrations, beats), iterates scenes and emits a `Cinematography` object per scene capturing four decisions:

```python
@dataclass
class Cinematography:
    color_grade: str        # red_tension | cold_blue | warm_brand | neutral_doc | urgent_amber | clinical_white
    transition_in: str      # cut | whip_pan | dissolve_flash | slow_fade | hard_cut
    motion: str             # slow_push | hold | fast_zoom | drift | parallax_lr
    voice_prosody: str      # hook_emphasis | urgent_problem | conversational | warm_cta | matter_of_fact
    reasoning: str          # 1-line WHY, logged for audit, not used at render
```

**Tool-call shim.** Gemma 4 supports function-calling but it is still uneven on small models. Instead of OpenAI-style tool schemas, the Cinematographer prompts gemma to return:

```json
{"calls": [
  {"tool": "set_color_grade", "args": {"scene": 0, "palette": "red_tension"}},
  {"tool": "set_transition",  "args": {"scene": 0, "kind":    "hard_cut"}},
  ...
]}
```

A helper `OllamaClient.generate_tool_calls(prompt, system, allowed_tools)` validates the shape and rejects calls to tools outside `allowed_tools`. Decisions are applied to `Scene.cinematography`. If the call fails or is malformed, the static `mood → effect` maps in `color_grade.py` and `transitions.py` become the fallback — current behavior preserved.

**Consumers update to read Cinematography first, fall back to mood:**

- `composer._render_scene_clip` → reads `scene.cinematography.color_grade` (was `scene.visual_concept.mood`).
- `composer._concat_with_transitions` → reads `scene.cinematography.transition_in`.
- `composer._render_scene_clip` / motion module → reads `scene.cinematography.motion`.
- `voiceover.synthesize` (Patch D) → reads `scene.cinematography.voice_prosody`.

**Color palette extension.** `color_grade.grade_filter_for_mood` becomes `grade_filter_for_palette(palette)` with six entries:

- `red_tension` — 12% red shift + soft vignette (current "problem")
- `cold_blue` — 8% blue shift + slight desaturation, sterile feel
- `warm_brand` — 6% warm tint + gentle vignette (current "brand")
- `neutral_doc` — no grade (documentary feel)
- `urgent_amber` — 10% amber + subtle contrast bump
- `clinical_white` — slight desaturation + +5% brightness (lab feel)

**Sourcer queries stay palette-agnostic** — Cinematographer's color decisions never modify Sourcer search strings. (Explicit decision: avoids over-constraining image retrieval.)

## Patch B — Cumulative-context Sourcer

**Changes to `video_agent/agents/sourcer.py`:**

1. Add a one-shot Gemma call at the top of `Sourcer.run()` that produces a `NarrativeThread`: per scene, 4-6 "topical anchor" keywords representing what the audience is *holding in their head* at that moment — cumulative, not just the current line. Stored on `Storyboard.narrative_thread: list[list[str]]`.

   *Example:* scene 4 about high-pH water, after scenes 1-3 about scaling in equipment → thread = `["pipe scaling", "equipment", "calcium ions", "high pH", "industrial water"]` — not just `["river", "algae"]`.

2. `scoring.context_match_score(caption, narration)` → `context_match_score(caption, narration, thread_keywords, hero_claim)`. Caption must overlap *thread* + *narration*, not just narration. Effective floor on `_MIN_CONTEXT_SCORE` rises.

3. **Cross-scene visual coherence check.** After all scenes have chosen assets, compute pairwise phash distance between adjacent chosen assets. If `dist(N, N+1) > coherence_threshold`, append a `visual_jump` flag to `scene[N+1].critic_notes.flags`. GlobalDirector consumes this when deciding whether to demand re-source.

**Storyboard schema bump:** `Storyboard.narrative_thread` added, default `[]`.

## Patch C — Real outro (CTA-as-final-scene + silent stinger)

**Strip the templated outro from `composer.compose_short_v2`:**

1. The Strategist's final beat is already a `cta` beat; Storyboarder fills it. Today the voiceover for that beat is rendered then **truncated**, and a hardcoded `_OUTRO_CTA_TEXT` is bolted on over a pre-rendered card. Stop doing that.

2. Render the final scene like any other scene, with a brand-template asset:

   - Background: brand-navy solid (`BRAND_NAVY_2`).
   - Logo from `assets/brand/logo.png` (read via new `BRAND_LOGO_PATH` config), centered top-third.
   - `hrsuindore.com` wordmark, clean type, bottom-third.
   - Motion: slow "logo settle" (scale 1.05 → 1.0, opacity 0.0 → 1.0 over first 0.6s, then hold). No Ken Burns.

3. CTA narration (the actual Strategist-written sentence) is rendered as part of the main voiceover pass — no truncation, no separate TTS call.

4. **Silent 2-second logo stinger** appended after the spoken CTA scene. Same brand card, no voice, crossfades in. Pure cinematic punctuation.

5. **Removed:** `_OUTRO_CTA_TEXT`, `_add_cta_voiceover`, `OUTRO_VIDEO_PATH` branch in compose path. `OUTRO_VIDEO_PATH` config key marked deprecated (kept for one cycle, then removed).

**New file:** `video_agent/visual_engine/brand_outro_card.py` — renders the final-scene brand card and the 2s stinger as separate clips.

## Patch D — Per-scene SSML prosody

**Changes to `video_agent/voiceover.py`:**

1. New signature variant: `synthesize_segments(segments: list[VoiceSegment], output_path, region)` where:

   ```python
   @dataclass
   class VoiceSegment:
       text: str
       prosody: str   # hook_emphasis | urgent_problem | conversational | warm_cta | matter_of_fact
   ```

2. Each segment is rendered via `edge_tts.Communicate(ssml=True, ...)` using SSML wrapped around `<prosody rate="..." pitch="...">` and `<emphasis level="strong">` for the hook.

   **Prosody presets (driven by `Cinematography.voice_prosody`):**

   | preset            | rate  | pitch  | emphasis                       |
   |-------------------|-------|--------|--------------------------------|
   | `hook_emphasis`   | -10%  | +2st   | `<emphasis>` on first NP       |
   | `urgent_problem`  | +5%   | +1st   | none                           |
   | `conversational`  | 0     | 0      | none                           |
   | `warm_cta`        | -5%   | -1st   | none                           |
   | `matter_of_fact`  | 0     | 0      | none                           |

3. Per-segment MP3s are concatenated with a 120ms inter-segment gap (matches natural beat-to-beat pause) into a single voiceover that the composer already expects. Downstream contract unchanged.

4. Old single-string `synthesize(narration, output_path, region)` retained as a thin wrapper that builds a single `conversational` segment — back-compat for any caller not yet on the Cinematographer path.

## Patch E — Gemma 4 thinking-mode in OllamaClient

**Changes to `video_agent/ollama_client.py`** (~30 lines):

1. `OllamaClient.__init__` gains `think_mode: bool = True`.
2. Sampling defaults change to `temperature=1.0, top_p=0.95, top_k=64` per gemma 4 spec sheet. Callers passing explicit `temperature` continue to win.
3. When `think_mode=True`, system prompt is prefixed with `<|think|>`.
4. Response post-processor strips the `<|channel>thought\n…<channel|>` block before returning. JSON parse runs on the stripped response.
5. **New helper** `generate_tool_calls(prompt, system, allowed_tools)` — used by Patch A. Validates response matches `{"calls": [{"tool": "...", "args": {...}}]}` shape, rejects calls to tools not in `allowed_tools`.
6. Inline comment flags the gemma 4 multi-turn rule (strip thoughts from history before next turn) for whoever adds multi-turn later. We don't use multi-turn today.

## Patch F — Persistent stealth browser for Google Images

**Changes to `video_agent/sources/google_images_browser.py`:**

1. **Replace hand-rolled stealth with `tf-playwright-stealth`** (maintained sync-API fork; vanilla `playwright-stealth` is async-only). One dependency add. Patches ~30 fingerprint vectors (Chrome runtime, WebGL vendor, permissions API, etc.).

2. **Persistent context across runs.** Switch from `chromium.launch()` + `new_context()` to `chromium.launch_persistent_context(user_data_dir="output/_browser_profile/google_images", ...)`. Cookies, the CAPTCHA-solved NID token, and the fingerprint profile survive between runs. Once a CAPTCHA is solved manually, Google trusts that profile for hours/days.

3. **One page, no churn.** Stop `new_page()`/`page.close()` per query. Open one page in `_init_browser`, reuse it across `_do_search` calls — just `page.goto()` to the next query URL. Visibly: same tab stays open, only the URL bar changes.

4. **Human-like motion helper `_human_browse(page)`** runs after page settles, before JS extraction:

   - Mouse drifts to a random point along a bezier curve (3-5 control points) via `page.mouse.move(x, y, steps=N)` — `steps` makes Playwright animate the movement instead of teleporting.
   - 1-2 wheel scrolls of random magnitude (300-900px) with 150-400ms jitter, replacing the current `window.scrollBy(0, 1800)` snap.
   - Occasional 600-1200ms idle "reading pause" before extraction.

5. **CAPTCHA path stays manual.** With the persistent profile, CAPTCHAs appear much less often. When one does, the same tab is already open — no jarring window pop. Headless mode also gets persistent profile benefits.

6. **Public API unchanged** — `search(query, limit)` is a drop-in for the Sourcer.

## Cross-cutting

- **Storyboard schema:** `version: "2.2"`; `Scene.cinematography: Cinematography | None`; `Storyboard.narrative_thread: list[list[str]]`. Old storyboards without these fall back to mood-based defaults — no migration.
- **Brand assets:** `assets/brand/logo.png` already added by user. Config: `BRAND_LOGO_PATH = "assets/brand/logo.png"`. Patch C reads it; existing `BRAND_LOGO_WHITE_PATH` left alone.
- **Optional hook/CTA watermark** — opt-in flag `WATERMARK_HOOK_AND_CTA = False` (default off; can be flipped per-video).
- **`quality_report.json`** gains a `cinematography` block per scene + a `narrative_thread` array, so you can audit *why* each image was chosen and what mood/prosody decisions the Cinematographer made.
- **No new Python deps** other than `tf-playwright-stealth`. Edge-tts SSML and ollama gemma-4 tags are already supported by installed versions.

## Out of scope

- Animation/motion graphics generation (still photos + Ken Burns + clip footage only).
- AI-generated featured images per blog (separate roadmap item).
- Real OpenAI-style function-calling protocol — the JSON-shim is intentionally simpler.
- Cross-platform browser profile sync (single machine only).

## Risks

- **Gemma 4 thinking-mode output adds tokens and latency.** Each agent stage gets slower. Mitigation: only enable for Strategist, Storyboarder, Cinematographer, NarrationPolisher. NOT for high-frequency calls.
- **Tool-call shim relies on JSON shape compliance.** Fallback to mood-based static maps is the safety net; logs flag every fallback so we can monitor failure rate.
- **Persistent browser profile can become stale or banned.** Profile lives under `output/` — deleting the dir is a clean reset.
- **SSML prosody quality varies by voice.** Some Edge TTS voices ignore pitch shifts. Mitigation: per-region voice already chosen; we validate the SSML compiles, not that it sounds dramatic. If hook still sounds flat after Patch D, escalate to a voice swap.
